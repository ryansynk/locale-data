# LOCALE Benchmark: SRA-4571

Given a sequencing read, find the SRA runs whose assembled contigs it aligns to. This is the large set: **4571 SRA runs** indexed, **10000 query reads**, ground truth from minimap2 alignment of each read against every run's [Logan](https://github.com/IndexThePlanet/Logan) contigs. Companion sets: [SRA-50 v2](https://huggingface.co/datasets/rsynk/locale-benchmark-sra50-v2) and [SRA-500 v2](https://huggingface.co/datasets/rsynk/locale-benchmark-sra500-v2), built by the same pipeline with the same filters.

Unlike the 50 and 500 sets, the runs here are not a sample: they are **every run of the [Metagraph 100-studies table](https://github.com/ratschlab/metagraph) that exists in Logan (5092), minus the 521 runs in the LOCALE training and validation sets**, with no size filters.

The repo also carries a **vector-search benchmark** built from the same queries: LOCALE embeddings of every contig of every run, reduced to 128 dimensions by PCA and stored as bfloat16 (830,307,954 vectors, 198 GB), plus query vectors and exact top-100 ground truth at each mutation rate. See [Embeddings](#embeddings).

| | |
|---|---|
| Runs indexed | 4571 |
| Queries | 10000 (from 2145 of the runs) |
| Relevant runs per query | mean 17.2, median 3, max 385 |
| Query length | 43 to 301 bp, mean 138 |
| Queries on the `-` strand | 5339 (53%) |
| Filter accounting | 4563409 sampled reads; 3653445 dropped for no hit to their own run, 1400 for hitting more than 915 runs, 712599 for overlapping another query; 195965 eligible, 10000 kept |
| Seed | 5000 (final shuffle only) |
| Excluded | the LOCALE training and validation runs (521) |

## How the ground truth was built

1. **Accession set.** Drawn from the SRA runs of the [Metagraph 100-studies table](https://github.com/ratschlab/metagraph) proportionally by organism, restricted to runs with at most 2M Logan contigs and at least 1 Mbp of assembled sequence, certified to exist in Logan at draw time, and with every run in the LOCALE training and validation sets removed from the pool before the draw. The draw is seeded, so `accs.txt` is reproducible from the seed.
2. **Queries.** The first 1000 spots of every run were streamed from SRA with `fastq-dump` (mate 1 for paired runs). Stored query sequences are the raw reads exactly as sequenced; nothing is trimmed or reverse-complemented.
3. **Alignment.** Every read was aligned with minimap2 (`-a --eqx`, both strands) against the Logan contigs of every run in the set, keeping the best alignment per (read, run) by exact-match count. An alignment counts when identity (exact matches / read length) exceeds 0.9.
4. **Filters**, per query, in this order: the run the read was sampled from must be in its relevant set; the read must not hit more than 20% of the runs in the set; the read must not share a contig region with another query (strict overlap filter with a 1024 bp chunk margin). Survivors are shuffled with the seed and the first N kept.
5. **Mutated copies.** The same queries with sequencing noise injected by [mutation-simulator](https://github.com/mkpython3/Mutation-Simulator) at SNP rate r with insertion and deletion rates r/10 each, r = 0.05 and 0.10. Every row keeps its `query_id` and ground-truth columns, so any method can be evaluated on identical mutated reads. The simulator's fasta and VCF per rate are under `mutations/`.

## Files

| File | Contents |
|---|---|
| `accs.txt` | the indexed SRA run accessions, one per line |
| `queries.parquet` | one row per query with its ground truth (schema below) |
| `queries_mut0.00.parquet` | `queries.parquet` plus a `mutation_rate` column (clean) |
| `queries_mut0.05.parquet`, `queries_mut0.10.parquet` | same rows in the same order with `query_sequence` mutated |
| `queries.fa`, `queries.fa.fai` | the clean queries as fasta (mutation-simulator's input) and its index |
| `mutations/` | mutation-simulator fasta and VCF for each rate |
| `embeddings/locale-pca128-bf16/` | the vector-search benchmark: base shards, query vectors, ground truth (below) |
| `score.py` | scores a result file against the ground truth; numpy + pyarrow only |

## Schema of `queries.parquet`

| Column | Type | Meaning |
|---|---|---|
| `accession` | str | run the read was sampled from |
| `query_id` | str | `<accession>.<spot>` from fastq-dump |
| `query_sequence` | str | the raw read |
| `contig_accession` | list[str] | **relevant set**: every run with an alignment above the identity threshold; always contains `accession` |
| `contig_id` | list[str] | best-aligned contig in each relevant run |
| `identity` | list[f64] | exact matches / read length of that alignment |
| `ratio` | list[f64] | contig length / read length |
| `contig_len` | list[i64] | contig length |
| `aln_interval_contig` | list[struct] | 0-based `[start, end)` of the alignment on the contig |
| `strand` | str | `+`/`-`: strand of the best hit to the source run |

The six list columns are parallel: element *i* of each describes the same alignment.

## Embeddings

`embeddings/locale-pca128-bf16/` is an ANN benchmark in the layout of [SRA-500](https://huggingface.co/datasets/rsynk/locale-benchmark-sra500)'s `embeddings/locale`, with one change: the vectors are LOCALE's 768-d output **projected to 128 dimensions by PCA and stored as bfloat16**, which is 12x smaller than fp32 at 768-d and loses little (table below). Given a read, the task is still to find the runs it aligns to; every base vector is labelled with its run by `meta.parquet`, and every query read with its relevant runs by `queries.parquet`.

```
embeddings/locale-pca128-bf16/
├── manifest.json        n, dim, dtype, num_shards, rows_per_shard, metric, encoder config, pca block
├── meta.parquet         srr_id, start_row, num_rows: rows [start_row, start_row + num_rows) belong to that run
├── projector.pt         (768, 128) fp32 torch tensor; projected = encoder_output @ projector
├── base/
│   ├── embeddings-00000.bf16bin   4,194,304 rows each (1.07 GB), the last one shorter
│   └── ...                        198 shards, 830,307,954 x 128 in total
├── mut0.00/  query.fbin · query_meta.parquet · gt.bin
├── mut0.05/
└── mut0.10/
```

**Base vectors.** Every contig of every run was cut into 256 bp windows with stride 106 bp (overlap 150), contigs shorter than 100 bp skipped, and each window embedded by LOCALE (checkpoint `8vqiabk9`, mean pooling; `manifest.json` records the encoder config). The 768-d unit-norm embeddings were projected onto the top 128 eigenvectors of a per-run-balanced sample's second moment (no centering), then rounded to bfloat16. The projected vectors are **not** unit norm; the metric is inner product. Shards concatenate in filename order and each header carries its own row count, so global row ids come from summing the shard sizes.

**Queries.** Every query read at each mutation rate, embedded the same way and projected with `projector.pt` in fp32, so `query.fbin` has the base's dimension and can be searched directly. The benchmark searches **both strands**: each query contributes its forward sequence and its reverse complement, each cut into non-overlapping 256 bp chunks. `query_meta.parquet` (`query_id`, `start_row`, `num_rows`, `num_forward`) maps rows back to queries; within a query's range the `num_forward` forward rows come first, then the reverse-complement rows. A scorer reduces over all of a query's rows (max score per run), as `score.py` does.

**Ground truth.** `gt.bin` holds the exact inner-product top-100 of every query row over all 830M base vectors, computed on the bfloat16 values upcast to fp32 with TF32 off, in the big-ann-benchmarks layout:

```
uint32 nq, uint32 k, uint32 ids[nq * k], float32 dists[nq * k]
```

**Reading the files.** The 2-byte files share the fbin header; numpy has no bfloat16, so map as uint16 and widen:

```python
import numpy as np
from pathlib import Path

def read_bf16bin(path):
    n, d = np.fromfile(path, dtype=np.uint32, count=2)
    raw = np.memmap(path, dtype=np.uint16, mode="r", offset=8, shape=(int(n), int(d)))
    return (raw.astype(np.uint32) << 16).view(np.float32)   # exact upcast

def read_fbin(path):
    n, d = np.fromfile(path, dtype=np.uint32, count=2)
    return np.memmap(path, dtype=np.float32, mode="r", offset=8, shape=(int(n), int(d)))

start = 0
for shard in sorted(Path("embeddings/locale-pca128-bf16/base").glob("embeddings-*.bf16bin")):
    x = read_bf16bin(shard)
    index.add_with_ids(x, np.arange(start, start + len(x)))   # global row ids
    start += len(x)
```

**Scoring.** Write your top-k as a `my_res.bin` in the `gt.bin` layout, one row per row of `query.fbin` (20,206 rows at mut0.00, 20,208 at the other rates), then

```
python score.py my_res.bin --bundle embeddings/locale-pca128-bf16 --mut 0.00 --queries queries.parquet
```

reports vector recall@k against `gt.bin` and the run-level metrics (recall@k, R-precision, AUPRC) after collapsing hits to runs by max score.

**Exact-search baseline.** Scoring `gt.bin` against itself gives the ceiling for any method over these vectors (vector recall is 1 by construction):

| Metric | mut0.00 | mut0.05 | mut0.10 |
|---|---|---|---|
| accession recall@1 | 0.3867 | 0.3287 | 0.1386 |
| accession recall@5 | 0.6802 | 0.5758 | 0.2667 |
| accession recall@10 | 0.7578 | 0.6449 | 0.3266 |
| R-precision | 0.8314 | 0.6820 | 0.3078 |
| AUPRC | 0.8733 | 0.7188 | 0.3301 |

For reference, exact search over the unprojected fp32 768-d embeddings (not published; 2.55 TB) reaches AUPRC 0.898 / 0.773 / 0.411 on a 1000-query subsample, so the PCA-128 bfloat16 reduction costs 0.03 to 0.08 AUPRC at 12x less storage. The absolute numbers are lower than on the 50- and 500-run sets because this is a 4571-way task with a mean of 17 relevant runs per query.
